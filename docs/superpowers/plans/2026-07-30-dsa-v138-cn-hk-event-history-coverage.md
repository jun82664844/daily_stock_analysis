# DSA V138 A股与港股历史事件覆盖实施计划

## 目标

在 V137 的缓存优先、三市场隔离和免 AI 边界上，提高 A 股与港股可计算历史事件覆盖率。

本阶段只展示公开来源已记录的日期、行情和同期比较数据，不生成事件因果结论、投资建议、目标价或交易指令。

## 已确认问题

1. 巨潮资讯可以返回指定 A 股的实际披露日期，但当前全市场截断顺序可能先丢失指定股票。
2. Yahoo 历史财报日期对部分港股覆盖不足，但公共图表可以返回已发生的除息、拆股等公司行动。
3. 事件窗口当前只读取约三个月行情，无法稳定覆盖更早的年报和公司行动。
4. 最终最多六条事件按全局时间截断，美股记录可能挤占 A 股和港股席位。

## 数据契约

- `provider_schedule + scheduled`：来源提供的计划日期。
- `provider_event_history + observed`：来源已经记录的历史公司事件日期。
- 新闻发布时间、抓取时间和模型推测不得作为事件日期。
- 每条数据必须保留来源、抓取状态、事件时间依据和市场标识。
- 三市场独立失败；一个市场不可用不能阻断其他市场。
- 全流程 `ai_used=false`、`informational_only=true`。

## 实施范围

### 后端

1. 公共日历在存在指定标的时，只保留这些标的及无证券代码的宏观事件。
2. 读取 Yahoo 公共图表中的历史除息和拆股记录，建立独立历史公司事件来源。
3. A 股实际披露日期标记为历史事件；未披露预约日期继续标记为计划事件。
4. 历史事件回看窗口扩展到最多一年，历史行情使用一年范围。
5. 最多六条结果按 A 股、港股、美股进行可用市场保底，再按时间填充。
6. API 返回 `event_time_kind` 与 `classification_source`，不混淆计划和已发生事件。

### 前端

1. 中文和英文分别展示“计划日期”和“历史公司事件”。
2. 来源说明覆盖巨潮资讯、Yahoo 公共日历和 Yahoo 公共图表。
3. 空状态和副标题不再只写“历史计划事件”。
4. 继续展示“同期表现不代表事件导致行情变化”的边界提醒。

### 配置与验收

- 新增 V138 历史覆盖开关和回看天数配置，生产示例默认关闭，本地环境显式开启。
- 新增 `scripts/verify_platform_event_history_coverage_v138.py`。
- 通过标记：`DSA_PLATFORM_EVENT_HISTORY_COVERAGE_V138_OK`。

## 验收标准

1. 确定性测试覆盖 A 股实际披露、港股历史公司行动、指定标的过滤和三市场均衡。
2. 中文和英文界面均能区分计划事件与历史公司事件。
3. 真实本地接口至少返回一个 A 股和一个港股可计算候选；若公共来源临时失败，必须如实降级。
4. 1、3、5、20 个交易日切换正常，点击证券可进入查询。
5. 不泄漏密钥，不调用 AI，不包含投资建议或因果措辞。
6. 历史门禁、前后端测试、构建、浏览器桌面与移动验收通过。
7. 完成本地提交后 Git 工作树干净，不推送远端。
